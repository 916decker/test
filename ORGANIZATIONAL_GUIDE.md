### 06 - Archive

**Purpose**: Store outdated or completed documents

#### When to Archive
- Projects that are completed (after 3 months)
- Outdated processes (when new version is created)
- Old versions of documents (keep final version in main folder)
- Previous year's materials (at year-end)

#### Organization
**By Project:**
- Create folder for each archived project
- Include ALL related documents

**By Year:**
- Archive annually
- Create `2025 Archives` folder at end of 2025
- Move all 2025 documents that are no longer active

**Don't Delete**: Archive instead of deleting (unless truly unnecessary)

## 📝 Naming Conventions

### File Naming Standard

**Format**: `YYYY-MM-DD_Category_Description_v#.ext`

**Components:**
- **Date**: When created (YYYY-MM-DD format)
- **Category**: Brief category (SOP, Template, Meeting, etc.)
- **Description**: Clear description (use underscores, not spaces)
- **Version**: v1, v2, etc. (optional for evolving docs)
- **Extension**: .pdf, .docx, .md, .jpg, etc.

### Examples

**Good:**
- ✅ `2025-11-01_SOP_Customer_Onboarding_v3.pdf`
- ✅ `2025-11-01_Meeting_Notes_Q4_Planning.md`
- ✅ `2025-10-15_Template_Proposal_Standard_v2.docx`
- ✅ `2025-11-01_Logo_Primary_White_1000px.png`

**Bad:**
- ❌ `onboarding.pdf` (no date, no context)
- ❌ `meeting notes nov 1.docx` (inconsistent format, spaces)
- ❌ `FINAL FINAL v3 updated.pdf` (messy version)
- ❌ `template (1).docx` (meaningless copy number)

### Special Suffixes

- `_DRAFT` - Work in progress, not final
- `_FINAL` - Approved final version
- `_TEMPLATE` - Reusable template
- `_ARCHIVED` - Old version being archived

### Folder Naming

- Use numbered prefixes for main folders (01, 02, etc.)
- Use Title Case (Capital First Letters)
- Use hyphens or underscores for separation
- Be descriptive but concise

## 🔄 Document Lifecycle

Every document goes through stages. Follow this lifecycle:

### Stage 1: Creation
**Status**: Draft
**Who**: Creator
**Actions**:
- Create from template (if available)
- Use proper naming convention
- Add to appropriate folder
- Mark as DRAFT in filename
- Color: 🟠 Orange

### Stage 2: Collaboration
**Status**: In Review
**Who**: Collaborators
**Actions**:
- Share with relevant team members
- Use Google Docs commenting feature
- Track feedback and changes
- Use version history
- Color: 🟡 Yellow

### Stage 3: Approval
**Status**: Ready for Approval
**Who**: Approver (manager/lead)
**Actions**:
- Submit for review
- Address feedback
- Make final revisions
- Get explicit approval

### Stage 4: Publication
**Status**: Final/Approved
**Who**: Creator or Admin
**Actions**:
- Remove DRAFT from filename
- Add FINAL suffix (if applicable)
- Set appropriate permissions
- Notify relevant team members
- Color: 🟢 Green
- ⭐ Star if frequently accessed

### Stage 5: Maintenance
**Status**: Active
**Who**: Document owner
**Actions**:
- Review quarterly
- Update as needed
- Increment version number if updated
- Archive old versions

### Stage 6: Archival
**Status**: Archived
**Who**: Admin or document owner
**Actions**:
- Move to Archive folder
- Update references to document
- Keep for records
- Color: 🟣 Purple

## 🏷️ Tagging & Color Coding

### Color Coding System

Use Google Drive's folder colors:

| Color | Meaning | Use Case |
|-------|---------|----------|
| 🔴 Red | Urgent/Critical | Needs immediate attention |
| 🟠 Orange | In Progress | Currently being worked on |
| 🟡 Yellow | Needs Review | Waiting for feedback/approval |
| 🟢 Green | Approved/Final | Completed and approved |
| 🔵 Blue | Reference/Template | Reusable resources |
| 🟣 Purple | Archive | No longer active |

### How to Apply Colors

1. Right-click on folder/file
2. Select color from the palette
3. Team members see the same colors

### Description Tags

Add tags to file descriptions in Google Drive:

**Format**: Use hashtags in the Description field

**Common Tags**:
- `#confidential` - Sensitive information, restricted access
- `#template` - Reusable template
- `#process` - Process documentation
- `#client-facing` - External documents
- `#internal` - Internal only
- `#ai` - AI-related content
- `#reviewed` - Reviewed and approved
- `#needs-update` - Outdated, needs revision

**How to Add**:
1. Right-click file → Get info
2. Add tags in Description field
3. Use for better searchability

### Starring System

**⭐ Star these files:**
- Frequently accessed documents
- Critical reference materials
- Active templates
- Current project docs

**Access starred files**:
- Click "Starred" in left sidebar of Google Drive
- Quick access to important docs

## 🔐 Permission Management

### Role Definitions

#### Admin
**Who**: Business owners, managers
**Access**: Full access to all folders
**Permissions**:
- Create, edit, delete, share
- Manage team permissions
- View all documents

#### Editor
**Who**: Team members, employees
**Access**: Department-specific
**Permissions**:
- Create and edit documents in their area
- Comment on documents
- Cannot delete or manage permissions

#### Viewer
**Who**: Contractors, external stakeholders
**Access**: Specific folders only
**Permissions**:
- Read-only access
- Can comment (if enabled)
- Can download (optional)

### Folder-Level Permissions

#### Public to Team (All can view/edit)
- ✅ Knowledge Base
- ✅ Templates (in Business Assets)
- ✅ Departmental Meeting Notes

#### Department-Based Access
- ✅ Business Processes folders (by department)
- ✅ Project-specific folders
- ✅ Marketing Materials (marketing team)

#### Restricted Access (Admins + Specific Roles)
- 🔒 Strategic Planning (Leadership only)
- 🔒 Legal & Contracts (Admin + Legal)
- 🔒 Finance docs (Admin + Finance team)
- 🔒 HR Policies (Admin + HR team)
- 🔒 Emergency & Critical Info (Admins only)

### How to Set Permissions

1. Right-click on folder
2. Click "Share"
3. Add team members by email
4. Set permission level:
   - Viewer
   - Commenter
   - Editor
5. Click "Send"

### Permission Best Practices

✅ **Do:**
- Give minimum necessary access
- Review permissions quarterly
- Remove access when people leave
- Use groups for team-wide access
- Document who should have access

❌ **Don't:**
- Give everyone admin access
- Share external links publicly
- Forget to remove contractor access
- Allow file downloads for sensitive docs

## ✨ Best Practices

### Daily Habits

**When creating a document:**
1. Use the correct folder
2. Use proper naming convention
3. Start from a template (if available)
4. Mark as DRAFT if not final
5. Set appropriate color

**When saving a document:**
1. Save in the right folder (not Desktop!)
2. Add description with tags
3. Set sharing permissions
4. Star if frequently accessed

**When collaborating:**
1. Use comments, not direct edits (for final docs)
2. Tag people in comments with @name

## 👥 Team Workflows

### Workflow 1: Creating a New SOP

1. **Identify Need**: Realize a process needs documentation
2. **Check Existing**: Search to see if SOP exists
3. **Start from Template**: Use SOP template from Templates folder
4. **Draft**: Write the SOP, mark as DRAFT
5. **Get Input**: Share with team members who do this process
6. **Revise**: Incorporate feedback
7. **Approve**: Get manager approval
8. **Publish**: Remove DRAFT, mark as FINAL, share widely
9. **Train**: Walk team through new SOP
10. **Review**: Set reminder to review quarterly

### Workflow 2: Onboarding New Team Member

**Day 1:**
1. Add to main Document Hub with Viewer access
2. Share orientation docs from Knowledge Base
3. Grant access to their department folders with Editor access
4. Show them this Organizational Guide
5. Walk through folder structure (15 min)

**Week 1:**
1. Share relevant SOPs and processes
2. Add to team meeting notes folders
3. Grant access to templates
4. Set up in shared contact lists

**Month 1:**
1. Review access levels
2. Upgrade to Editor where appropriate
3. Get feedback on documentation
4. Update onboarding process if needed

### Workflow 3: Starting a New Project

1. **Create project folder** in appropriate area
2. **Copy templates** to project folder
3. **Set permissions** for project team
4. **Create project brief** doc
5. **Link to relevant resources** from Knowledge Base
6. **Share with stakeholders**
7. **Update regularly** throughout project
8. **Archive when complete** (after 3 months)

### Workflow 4: Running Effective Meetings

**Before Meeting:**
1. Create agenda doc from template
2. Share with attendees 24hrs before
3. Add to appropriate Meeting Notes folder
4. Set color to Orange (in progress)

**During Meeting:**
1. Take notes in the shared doc
2. Mark action items clearly
3. Assign owners and due dates

**After Meeting:**
1. Clean up notes
2. Share summary via email/Slack
3. Mark color as Green (complete)
4. Follow up on action items
5. Create next meeting doc if recurring

### Workflow 5: Updating Templates

**When you improve a template:**
1. Make a copy of current template
2. Rename copy with version number increased
3. Move old version to Archive
4. Make improvements to new version
5. Mark as FINAL
6. Announce to team with change notes
7. Update any linked documentation

## 🔍 Search & Discovery

### Basic Search

**In Google Drive search bar:**
- Type filename or keywords
- Results show all matching files

**Pro tip**: Use the filters on left sidebar
- File type
- Owner
- Modified date

### Advanced Search Operators

**In Google Drive search:**

| Operator | Purpose | Example |
|----------|---------|---------|
| `type:` | Find by file type | `type:pdf` |
| `owner:` | Find by owner | `owner:john@company.com` |
| `title:` | Search in title only | `title:"meeting notes"` |
| `modified:` | By modification date | `modified:2025-11-01` |
| `before:` | Before date | `before:2025-10-01` |
| `after:` | After date | `after:2025-09-01` |

**Combine operators:**
- `type:pdf title:"SOP" modified:2025-11-01`

### Finding What You Need

**Looking for a template?**
1. Go to `03 - Business Assets/Templates/`
2. Or search: `type:document title:template`

**Looking for an SOP?**
1. Go to `02 - Business Processes/Operations/SOPs/`
2. Or search: `title:SOP`

**Looking for meeting notes?**
1. Go to `05 - Important Information/Meeting Notes/`
2. Or search: `title:"meeting" modified:2025-11-01`

**Looking for old version?**
1. Check Archive folder
2. Or use version history: File → Version history

### Can't Find It?

**Ask yourself:**
1. What category does it fall under?
2. Who created it?
3. When was it created?
4. What was it called?

**Then:**
- Browse the category folder
- Search by owner
- Search by date range
- Ask the team in Slack/email

## 📞 Getting Help

### Common Questions

**Q: Where do I put this document?**
A: Think about what category it fits in. If unsure, ask in team chat or put in "Important Information" temporarily.

**Q: Can I create my own folders?**
A: Within your department folders, yes! But don't add top-level folders without team discussion.

**Q: What if I need to share something externally?**
A: Create a copy, put it in a separate "External Sharing" folder, and share that. Don't give external access to main folders.

**Q: How do I delete something?**
A: Don't delete - move to Archive instead. Only admins should permanently delete.

**Q: The structure doesn't fit my use case**
A: That's okay! Adapt it to your needs. Just keep the team informed.
